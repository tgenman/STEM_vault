# проверка изменений

Глубина проверки зависит от типа изменения. Содержательный патч, работа со ссылками, структурная операция и Anki — разные пакеты и не должны молча объединяться.

## пошаговый перебор корпуса

- Бери небольшой осмысленный пакет связанных объектов, который можно понять и обсудить за один цикл.
- Сначала проводи read-only triage: прочитай объекты, необходимые источники, связи и текущее состояние. Content-, metadata-, link-, structural- и Anki-решения разделяй, если у них нет общего основания.
- Сразу предлагай конкретную судьбу каждого объекта: оставить, изменить, отложить конкретный вопрос или исключить по роли. «Просмотрено» означает, что информации достаточно для решения, а не что объект полностью исправлен.
- После ответа Дмитрия применяй согласованные правки, проверяй результат и переходи к следующему безопасному пакету без дополнительного приглашения.
- По умолчанию ход перебора живёт в текущем обсуждении. Отдельные реестры, baseline и отчёты создаются только по прямому запросу Дмитрия.

## перед изменением

- Проверь Git status parent и child и зафиксируй существующие пользовательские изменения.
- Для содержания перечитай целевой фрагмент, источник и необходимый локальный контекст.
- Для ссылок и структуры используй корневой Obsidian `zettle_life`: проверь точные цели, backlinks, совпадающие имена и unresolved targets.
- Для rename, move или delete сначала покажи Дмитрию точное отображение старых путей в новые.
- Anki scan не является проверкой Markdown и запускается только отдельной прямой командой.

## после изменения

- Перечитай каждый изменённый файл и проверь сохранность смысла, обозначений, frontmatter, ссылок и локального стиля.
- Подтверди разрешение новых внутренних ссылок или перечисли намеренные исключения.
- Для структурной операции повторно проверь backlinks, unresolved targets, встраивания и обе Git-зоны из полного корневого графа.
- Запусти `git diff --check`, изучи полный diff согласованных путей и повторно проверь оба Git status.
- Убедись, что существующие пользовательские изменения не были отредактированы, staged или включены в commit.

## критерий результата

- Ясно перечислены изменённые файлы и принятые решения.
- Подтверждённые факты, выводы по косвенным признакам, неоднозначности и непроверенные утверждения различены.
- Проверка соответствует реальному риску изменения; отсутствие общей команды сборки не заменяется выдуманным тестом.
- Anki ID и внешняя коллекция проверяются только в отдельно согласованном Anki-пакете.
