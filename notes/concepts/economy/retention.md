> [!tip] retention
> **User retention** — удержание пользователей, измеряемое долей пользователей исходной когорты, которые после стартового события выполнили заданное событие возврата в определённый период.

Пересказ документации Amplitude. Здесь рассматривается событийное удержание пользователей; определение не описывает удержание выручки или подписок.

## параметры расчёта

Задать стартовое событие и когорту, событие возврата, интервал времени и правило возврата. Например: регистрация → первая неделя → выполнение целевого действия.

## варианты

Названия Amplitude:

| Вариант | Условие возврата |
|---|---|
| Return On / N-Day | событие в конкретном интервале после старта, например в день 7 |
| Return On or After / Unbounded | событие в заданном интервале или позже, в пределах доступного наблюдения |
| Return On (Custom) | событие в заданном пользовательском диапазоне интервалов |

## формула для Return On

Запись по определению для одной когорты, не цитата формулы из документации:

$$
R_k = \frac{|\{u\in C_k: u\text{ выполнил событие возврата в интервале }k\}|}{|C_k|}\cdot100\%
$$

$C_k$ — пользователи когорты, для которых интервал $k$ полностью наблюдаем; $|C_k|>0$. Числитель считает уникальных пользователей, а не события.

Иллюстративный пример: из 100 пользователей с завершённым наблюдением дня 7 вернулись 25; D7 Return On retention = 25%.

## условия сравнения

Не смешивать Return On и Return On or After. Фиксировать часовой пояс и способ отсчёта времени: календарные даты и 24-часовые окна могут давать разные результаты. Недавние когорты ещё не имеют полного наблюдения поздних интервалов.

[[CSAT]] описывает ответы об удовлетворённости, retention — наблюдаемое возвращение по выбранному правилу.
